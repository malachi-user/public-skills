# Narrative and presenter experience

## Build the argument before the slides

Capture: audience, context, duration, objective, one remembered message, desired action, proof available, presenter credibility, and likely objections.

Use this default timing shape when no stronger structure fits:

- Opening: about 15%. Earn attention, establish relevance, and state what the audience will gain.
- Body: about 70%. Organize around at most three memorable ideas, each with proof, example, demo, story, or contrast.
- Close: about 15%. Synthesize, make the action specific, and close a loop opened at the start.

Plan an attention change every 5–10 minutes: a question, story, live interaction, striking visual, physical pause, demo, short clip, or temporary blank screen. Do not add more information merely because attention fell.

## Slide-plan schema

For every slide record:

| Field | Purpose |
|---|---|
| ID | Stable code/notes reference independent of slide order |
| Job | The single thing this slide must accomplish |
| Message | One sentence the audience should understand |
| Visual | The focal visual or composition |
| Reveal | What appears in which order |
| Speaker beat | What the presenter says/does, not text copied onto the slide |
| Time | Target minutes or seconds |
| Transition | The bridge into the next slide |
| Fallback | Backup if a demo, link, network, or audience interaction fails |

The sum of slide timings must match the talk duration. Also define a shortened route: which slides/fragments can be skipped without breaking the argument.

## Presenter controls

For web decks, prefer:

- Arrow/space navigation plus visible progress and slide number.
- Left click to advance only outside interactive elements.
- Right click to go back only in presentation mode.
- `F` for fullscreen and a documented blank-screen shortcut.
- A subtle per-slide `data-time-hint` visible to the presenter without competing with content.
- Focus management so keyboard navigation works without a first click.
- Hash URLs for direct access to a slide during rehearsal.

Exclude links, buttons, form controls, text selection, and edit mode from click-to-advance handlers.

## Speaker notes

Write notes as beats, not an essay:

1. Purpose.
2. Suggested wording.
3. Interaction or pause.
4. Proof/demo cues.
5. Transition sentence.
6. Target time.
7. Fallback or cut instruction.

Prepare demo tabs, credentials, local screenshots/video, and an offline copy before the event. Never let a live demo be the only way the audience can understand the point.
